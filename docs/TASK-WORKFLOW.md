# Task, test and review

The composer’s **Task → test → review** control creates a sibling Git worktree from the source chat’s reviewed HEAD. The source must be clean and committed; queued prompts and unsaved editor drafts must be resolved first. Configure test executables under **Settings → Project actions**. Select one to ten actions, enter the task, review the exact executable, arguments, directory and source commit, then start.

The new chat runs in `.grok-workbench-tasks/<UUID>` beside the source checkout. Workbench preserves the source chat’s selected model category and mode when available; otherwise it uses Grok defaults. Ordinary project trust and one-time tool approvals still apply. Workbench executes the selected tests after a successful agent turn, with captured exit codes and bounded output. Changes to the approved test action stop the workflow for review. There is one managed workflow at a time; unrelated running agents/actions prevent workspace mutation and test startup.

Open the task chat to inspect results and review its changed files. Select the files you want, **Preview selected files**, then explicitly **Apply reviewed files**. The source checkout must still be clean. The reviewed patch and target commit are rechecked before Git applies and stages the selected changes. Binary files are supported by Git binary patches; symlink changes are refused. Renames are represented as separate deletion/addition entries, so select both sides when applying a rename. Unselected changes remain in the task worktree. Applying does not commit, push, publish or remove the task checkout.

Cancellation stops the owned agent or test process tree. Failed tests retain their output and checkout. Restarted tasks are marked interrupted and never replayed automatically. Continue the preserved chat or rerun tests manually through Project actions. Worktree Tools provide recoverable archive/restore; ignored artifacts must be preserved separately before archive. Workflow metadata keeps the newest 100 records and the last 20,000 characters of each test result; the underlying chats and worktrees have separate retention controls.

Live OAuth acceptance on October 9, 2026 passed through the GUI: the embedded agent edited `value.txt` in a disposable task worktree, the configured Node test printed `LIVE_MANAGED_TASK_TEST_OK`, the original checkout stayed unchanged until review, and explicit apply staged the selected edit. The repeatable opt-in procedure is `npx tsx scripts/task-workflow-acceptance.ts --run`; it uses the existing OAuth profile without copying credentials. Deterministic tests separately cover failed tests, cancellation, restart recovery, stale commands, stale patches and path selection.
