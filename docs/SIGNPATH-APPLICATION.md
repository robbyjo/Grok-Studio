Tagline: An open-source desktop workbench for AI-assisted software development with Grok.

Description: Grok Workbench is an Apache-2.0 desktop application that helps developers work with local projects using Grok. It brings coding conversations, source editing, terminals, test execution and change review into one interface, with explicit approvals for agent actions. The project currently targets portable Windows use, with macOS and Linux planned.

Reputation: This is a new independently maintained project, created on October 7, 2026. It does not yet have an established user community or independent media coverage. As checked on October 9, the public repository has zero stars and forks, and the v0.7.0 executable has two recorded GitHub downloads. Public evidence includes the [repository](https://github.com/robbyjo/Grok-Workbench), [releases](https://github.com/robbyjo/Grok-Workbench/releases), [automated validation](https://github.com/robbyjo/Grok-Workbench/actions) and [validation records](VALIDATION.md). Current releases are locally built and unsigned. A GitHub-hosted CI artifact signing/publication pipeline is prepared for future releases; successful hosted acceptance and SignPath enrollment remain gates.

The optional download field asks for a page with existing SignPath Foundation signing attribution. Leave it blank while sponsorship is pending. The releases link is included in the reputation answer without claiming sponsorship. Leave Wikipedia/company fields blank unless applicable and confirmed by the owner.

The owner supplies the account's first name, last name and email directly in the form. Do not commit those contact details, credentials or tokens. The owner reviews the [Foundation terms](https://signpath.org/terms) and [SignPath privacy policy](https://signpath.io/privacy-policy), then approves the required Code of Conduct/certificate and personal-data consent. Optional marketing consent stays unchecked unless requested. A CAPTCHA, if shown, requires human action or explicit action-time confirmation.

GitHub MFA is confirmed by the owner. Before signing is enabled, configure SignPath MFA and confirm named author/reviewer/signing-approver roles. Include the [signing policy](CODE-SIGNING-POLICY.md), [license inventory](../DEPENDENCY-LICENSES.txt), [native/third-party packaging disclosures](SIGNPATH.md) and [release gates](RELEASE-GATES.md) during onboarding. Approval and dependency eligibility are decisions for the Foundation.
