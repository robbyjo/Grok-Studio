## 0.3.0 chat and project acceptance

Removal rejects running, approval and connecting chats in the project without applying a simultaneous rename; invalid names and unknown project IDs also leave state intact.

## Not yet validated

- Account expiry/refresh and broader account/model catalog availability beyond the observed signed-in profile.
- Client-managed HTTP OAuth provider lifecycle, MCP prompt/resource enumeration, exhaustive managed/compat-source policy interoperability, marketplace management and subagent/background events.
- Clean-machine portability, cross-machine credential portability, signing, auto-update, Windows ARM64, large histories and sustained concurrent-session performance.
- macOS/Linux builds and OS-specific agent sandbox behavior.

The isolated deterministic ACP fixture proves client protocol/state behavior; it does not establish Grok model quality or full Codex feature parity. Use [LIVE-ACCEPTANCE.md](LIVE-ACCEPTANCE.md) for the signed-in gate. Before everyday use, sign in to Grok and run a small temporary-repository task: read files, request an edit, approve/reject a shell command, stop a long command, resume after restart, switch advertised model/mode, and verify no unrelated files change.
