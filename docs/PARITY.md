## Execution and evidence limits

Electron main owns filesystem/Git/process operations behind an allowlisted, sender-validated preload. Native extension methods are finite and constructed by the backend, not accepted as arbitrary renderer RPC. Catalog and initialization persistence exclude configured MCP header/env/setup values. Direct source editing intentionally displays the selected user's configuration, which can include secrets; that text is not stored in desktop state.

Rewind requires a native dry run, explicit GUI confirmation, a second conflict-free dry run, file hashes and an immutable file/transcript recovery record before native execution. Git chunk and push operations check the reviewed state. These hashes are stale-review checks, not OS locks against external writers. Repository hooks and explicitly configured actions execute as the current Windows user. Setup actions are manual. Archive writes its recovery ref before removing a checkout.

Grok owns account authentication. Normal launches do not copy account credentials. Optional authenticated acceptance scripts can make a temporary local copy in an isolated profile and verify deletion; cross-machine transfer requires separate explicit authorization. HTTP MCP local logout deletes only the selected canonical credential key; provider consent and configured bearer headers remain. GitHub STDIO tokens live inside the server process; clearing them waits for native process shutdown.

Actual model/provider acceptance is documented separately from fixtures in [LIVE-RESULTS-2026-10-07.md](LIVE-RESULTS-2026-10-07.md), [GITHUB-MCP.md](GITHUB-MCP.md) and [VALIDATION.md](VALIDATION.md). No parity percentage is claimed.
