# Privacy and local data

Grok Workbench stores chats, task metadata, drafts, attachments, generated media, terminal scrollback, diagnostics and account configuration in its profile. Portable profiles remain beside the executable in `Grok Desktop Data`. Local editor workers do not use remote language services. Profile backup/migration copies private application data, including authentication files and encrypted API-key storage, into the profile’s `updates/profile-backups`; these backups are not uploaded or exported automatically. Protect them like the original profile. Windows encrypted credentials remain tied to their account/machine.

Grok authentication and prompted agent/media requests communicate with xAI. Requests can include prompts, explicitly attached files, and workspace/tool context selected by the native agent after applicable trust and tool approvals. Configured MCP servers, hooks, extensions, terminal commands and project actions can communicate with their configured providers and execute with the Windows user’s permissions. Review their trust, scopes and privacy policies. Agent approval controls do not provide OS containment.

Explicit update checks/downloads contact GitHub. GitHub CLI PR listing, push and reviewed remote review submission contact GitHub when invoked. Optional Windows notifications show brief task/approval notices locally. Application diagnostics are bounded local logs; Workbench does not add an automatic crash-log upload service. The embedded Grok library owns its authentication and any upstream telemetry behavior; this policy does not promise all native network activity is disabled. Check its effective configuration and xAI account privacy settings. Media generation does not silently change coding-data retention.

Relevant providers include [xAI privacy](https://x.ai/legal/privacy-policy), [GitHub privacy](https://docs.github.com/en/site-policy/privacy-policies/github-general-privacy-statement), and whichever MCP/plugin services you configure. Delete/export chat records through history controls; preserve native sessions and worktrees before pruning. To remove a portable installation, close Workbench and remove the executable and its adjacent profile after preserving needed data; Git worktrees and projects are separate folders. No paid cloud signing account or billing resource has been created.
